# Design decisions

| # | Decision | Why |
|---|----------|-----|
| 1 | `BHEEM_PROJECT_SPEC.md` is authoritative for gameplay, numbers, world structure, enemies, weapons and boss. | The attached `design.md` describes a different game (RUINFALL). |
| 2 | From `design.md` only the visual/UI language is used: 1px-outlined pixel art, violet occupation / gold liberation palette, cyan status line, damage numbers and "CRITICAL HIT" pops, dusk parallax, star-rated victory. | Compatible with BHEEM and matches the reference images. |
| 3 | Not implemented from RUINFALL: 60 s Ruin Clock, Ruin Wall, Emberhold hub, world-map sorties, slime/bat roster, pylon boss, five regions. | They conflict with the BHEEM spec's continuous village and Kaalasura boss. |
| 4 | All art is procedural (generated at boot into canvas textures). The supplied reference sheet is not embedded. | The sheet carries a stock watermark / unknown license. A licensed pack can be dropped in via `src/assets/manifest.ts` (`ART_STYLE`) without touching game code. |
| 5 | Pixel font is a built-in 5×8 bitmap font registered as a Phaser RetroFont. | No external font dependency; crisp at 2× scale. |
| 6 | Pure logic (damage, statuses, rally, economy, loot, boss selection, district FSM, RNG, time, save, level validation) lives in framework-free modules under `src/logic`, `src/core`, `src/systems`, `src/level`. | Unit-testable with Vitest without Phaser. |
| 7 | All tuning numbers live in `src/config/balance.ts`. | Single source of truth for balancing. |
| 8 | Level is data (`src/level/village.level.json`, generated by `scripts/build-level.mjs`) and validated + reachability-checked at load and in tests. | Content changes without code changes; unreachable platforms are caught in CI. |
| 9 | Arena platforms were lowered from y=930 to y=945 (rise 95 px ≤ 100 px max jump rise). | Reachability test flagged them. |
| 10 | Input latches key-down events between polls. | Very short taps (and synthetic test input) would otherwise be missed by per-frame `isDown` polling. |
| 11 | Hit-stop and slow-mo go through one priority-based `TimeController`. | Prevents competing effects from fighting over time scale. |
